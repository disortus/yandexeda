# Validator layer

## Назначение
Validator-слой отвечает за бизнес-валидацию, которую нельзя выразить только аннотациями DTO.

Пример: `@Email` проверит формат, но не проверит, что email уже занят.

---

## Два уровня валидации в Spring-приложении

### 1) Структурная (формальная) валидация
Делается через Bean Validation в DTO:

- `@NotBlank`
- `@Size`
- `@Email`

Срабатывает на этапе `@Valid` в контроллере.

### 2) Бизнес-валидация
Делается в validator/service:

- проверка уникальности
- проверка состояния домена
- ограничения предметной области

---

## Как реализовано в проекте

`UserValidator.validateForCreate(request)`:

1. Нормализует email (`EmailUtils.normalize`)
2. Проверяет `repo.existsByEmailIgnoreCase(email)`
3. Бросает `BusinessValidationException`, если правило нарушено

---

## Аннотации

### `@Component`
Регистрирует валидатор как Spring бин, чтобы его можно было внедрять через конструктор в сервисы.

---

## Best practices

1. DTO-валидация и бизнес-валидация должны дополнять друг друга.
2. Логику проверки не разбрасывай по контроллерам — держи централизованно.
3. Формулируй сообщения ошибок так, чтобы API-клиент мог их понять.
4. Если проверка используется в нескольких местах — выноси в отдельный validator.
