# Enums в проекте (`src/main/java/com/example/demo/enums`)

Эта папка хранит перечисления (enum), которые фиксируют **ограниченные наборы значений** в домене и инфраструктуре.

Enum — это отличный инструмент для учебного и боевого кода, потому что он:

1. устраняет "магические строки",
2. уменьшает количество ошибок из-за опечаток,
3. делает код самодокументируемым,
4. упрощает валидацию и поддержку API-контрактов.

---

## Какие enum используются в проекте

### 1) `UserRole`

Роли пользователя в системе:

- `CUSTOMER`
- `ADMIN`
- `COURIER`

Именно этот enum определяет права доступа в security-слое через `@PreAuthorize` и правила `SecurityFilterChain`.

Дополнительный метод:

- `asAuthority()` → `ROLE_<NAME>`

Это важно, потому что Spring Security по умолчанию работает с authority в формате `ROLE_...`.

### 2) `TokenType`

Тип токена в ответе авторизации. Сейчас используется:

- `BEARER`

Даже если тип пока один, enum полезен: API-контракт сразу явно показывает ограниченность значения и остаётся расширяемым.

### 3) `ApiErrorCode`

Единые коды ошибок, которые возвращаются клиенту в `ApiErrorResponse.code`:

- `RESOURCE_NOT_FOUND`
- `BUSINESS_VALIDATION`
- `REQUEST_VALIDATION`
- `AUTHENTICATION_FAILED`
- `ACCESS_DENIED`
- `INTERNAL_ERROR`

Это помогает фронтенду/клиентам опираться не только на HTTP-статус, но и на стабильные машинно-читаемые коды.

---

## Почему enum лучше строк

Сравним:

- ❌ `if (role.equals("ADMINN"))` — легко допустить опечатку
- ✅ `if (role == UserRole.ADMIN)` — compile-time safety

Плюсы enum-подхода:

1. IDE подсказывает допустимые значения,
2. рефакторинг безопаснее,
3. в Swagger и DTO отображается ограниченный набор,
4. проще централизованно менять доменную модель.

---

## Где enum участвуют в проекте

1. **Entity слой**: `User.role` хранится как `@Enumerated(EnumType.STRING)`
2. **DTO слой**: `UserCreateRequest.role`, `UserResponse.role`, `AuthResponse.tokenType`
3. **Security слой**: построение authority и role-based ограничения
4. **Exception слой**: возврат унифицированных `ApiErrorCode`
5. **OpenAPI**: enum значения отображаются в схемах Swagger

---

## Важная практика: хранить enum в БД как STRING

В проекте роли сохраняются строками, а не ordinal-индексом. Это правильно, потому что:

- порядок enum-констант может измениться,
- ordinal тогда "поедет" и сломает данные,
- строка остаётся стабильной и читаемой.

Поэтому для JPA корректно:

```java
@Enumerated(EnumType.STRING)
private UserRole role;
```

## Рекомендации по расширению enum

Если ты добавляешь новое значение (например, `MODERATOR`):

1. добавь константу в enum,
2. обнови security-правила,
3. обнови документацию/Swagger,
4. проверь тесты авторизации,
5. проверь совместимость с существующими данными и миграциями.

---

## Итого

Папка `enums` — это централизованная точка для фиксированных доменных и инфраструктурных значений.  
Для учебного Spring Boot проекта это особенно полезно: ты сразу привыкаешь к типобезопасному и предсказуемому подходу, который затем легко переносится в production-практику.
